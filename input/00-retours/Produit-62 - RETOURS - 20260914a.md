## digit-ai-forge-design (oracle-tokens)

| id | Gravité | Portée | Retour (fait observé, avec preuve : fichier, message, mesure) | Proposition esquissée |
|---|---|---|---|---|
| RD-18 | bloquant | générique | **La règle T1 compte la valeur de REPLI d'un `var(--jeton, <valeur>)` comme une couleur en dur, et rend un bloquant sur la forme même qu'elle réclame.** Fait mesuré le 2026-09-14 sur les deux pages de ce produit : **13 constats** `bloquant` T1 de la forme « couleur en dur « #475569 » sur color : passer par var(--token) », sur `.contenu`, `.termes`, `.termes dfn` (feuille de base du socle) et sur les sept règles du composant arborescent. **Les treize déclarations incriminées passent déjà par un jeton** : `.contenu { color: var(--muted, #475569) }`, `.arbre-chevron { background: var(--surface, #FFF); color: var(--muted, #64748B) }`, `.arbre-commandes button:hover { border-color: var(--blue, #2563EB) }`. La valeur citée par le message n'est jamais la couleur appliquée : c'est le repli, la valeur de secours si le jeton n'existe pas. Lecture du code : `PROPS_COULEUR` capture la valeur entière de la déclaration (`([^;]+)`, ligne 107 d'`oracle-tokens.mjs`) puis `findColors(val)` y cherche des littéraux — **rien n'écarte l'intérieur d'un `var()`**. Fixture double sens jouée le 2026-09-14 : un fichier posant `.a { color: #475569 }` et un fichier posant `.a { color: var(--muted, #475569) }` avec `--muted` défini au `:root` rendent **le MÊME constat bloquant T1** ; le second devrait passer. Conséquence, et elle est perverse : le lot 20260911c avait remonté RS-01, dont le remède (1) était « corriger les assets à la source — couleurs en dur passées en jetons ». **Le socle l'a fait, en `var(--jeton, repli)` — et l'oracle continue de crier.** Un auteur qui suit le remède voit son verdict inchangé ; le seul geste qui éteint le constat est de SUPPRIMER le repli, c'est-à-dire de rendre le composant fragile quand le jeton manque. *Une règle qui punit la forme défensive de ce qu'elle exige apprend à écrire du CSS moins robuste.* | **(1)** Avant de chercher des littéraux, neutraliser le contenu des `var(...)` dans la valeur — le repli n'est pas la couleur appliquée, il n'est appliqué que si le jeton est absent. **(2)** Ou, plus fin, ne juger le repli que s'il n'existe AUCUNE définition du jeton nommé dans la feuille : là, le repli EST la couleur servie et le constat est juste. **(3)** Fixture double sens : `.a { color: var(--muted, #475569) }` avec `--muted` défini au `:root` passe ; `.a { color: var(--absent, #475569) }` sans définition, et `.a { color: #475569 }`, échouent. |
